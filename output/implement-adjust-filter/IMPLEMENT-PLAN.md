### Assumptions and invariants carried from the design

- New public contract names are fixed here so implementation does not need to choose an API boundary: `VideoAppearance`, `VideoAdjustments`, `VideoLevels`, `VideoFilter`, `VideoFilterTexture`, `AppearanceUpdateResult`, and `AppearanceRejectionReason` in `com.cii.videolib`. Story-01 first establishes `VideoAdjustments`/`VideoLevels` and the result seam; Story-02 adds `VideoAppearance` with its filter property and makes the complete-snapshot operation authoritative, so each task compiles in DAG order.
- `VideoPreview.setAppearance(VideoAppearance)` is the authoritative complete-snapshot operation. `setAdjustments`, `resetAdjustments`, `setFilter`, and the fourteen named single-control setters are convenience operations that derive a complete immutable candidate and use the same validation/apply transaction; `null` passed to `setFilter` means removal. No setter clamps input.
- `AppearanceUpdateResult.Accepted` covers both immediately applied and detached-but-retained valid updates. `AppearanceUpdateResult.Rejected(reason, diagnostic)` carries a stable typed reason; the optional driver diagnostic is bounded and never includes shader source or texture bytes.
- `VideoFilterTexture` copies caller RGBA8888 bytes at construction and never exposes mutable owned storage. `VideoAppearance`, `VideoAdjustments`, `VideoLevels`, and `VideoFilter` are immutable value contracts.
- The internal native transport is one synchronous complete-snapshot call named `VideoPreview.nativeApplyAppearance`; its exact paired export is `Java_com_cii_videolib_VideoPreview_nativeApplyAppearance`. A package-private `NativeAppearanceResult` carries native result code plus bounded diagnostic back to Kotlin. JNI copies strings, arrays, and texture bytes before the call returns; no `JNIEnv*`, local reference, or caller buffer crosses threads.
- New internal native value/result symbols are fixed as `AppearanceSnapshot`, `AdjustmentSnapshot`, `FilterDescriptor`, `FilterTexture`, `AppearanceApplyResult`, and `AppearanceError` under the bounded new header `videolib/src/main/cpp/appearance.h`.
- Existing embedded C++ shader strings remain the library-owned packaging mechanism. No asset or CMake source-list change is planned. The RGBA decode/input contract and the existing quad/primary upload remain authoritative.
- All values and ranges, levels ordering, filter-first adjustment order, version-1 entry point/sampler ABI, surface rules, failure behavior, and rollback are exactly those in design D-05–D-10 and the design's adjustment/boundary tables.
